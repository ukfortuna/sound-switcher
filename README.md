# Steam Sound Switcher

A Millennium plugin prototype with a Turkish settings menu for custom **private-message notification sounds**. Target environment: Millennium v3.6.2 on Windows. This is source code, not a ready-to-install release.

**Status:** thirteen isolated runtime/audio/settings tests pass. Starlight compilation, menu rendering, RPC payload limits, and actual Steam message interception have NOT been verified. Do not advertise this version as compatible until the acceptance checklist passes on a real Steam installation.

## Menu

- Choose WAV, MP3, OGG or M4A (browser decoding support applies).
- Preview locally, set volume, save or restore Steam defaults.
- Maximum input: 5 MB and 10 seconds. Audio is converted locally to PCM16 WAV.
- Settings and imported audio persist in a separate local settings.json file under Steam/millennium/config/sound-switcher. This avoids the 256 KB config-value limit. They are installation-wide, not per Steam account.
- Imported audio is not uploaded by this plugin. No sound packs are bundled.

## Build and local installation

Install Bun first using https://bun.sh/docs/installation and keep Millennium installed.
Open a terminal in this repository:

```powershell
bun install
bun run test
bun run build
```

This update defaults to `auto`, which installs into the local Millennium installation. Set `output_path = "dist"` for a distributable build without local installation. This build has not been run here because the package registry was unreachable. The first successful build must also establish the exact output layout.

For a local development installation, keep `output_path = "auto"` in `millennium.toml`, then run `bun run build`. The official compiler documents `auto` as detecting the local Millennium installation and installing there. This writes the compiled plugin to your Millennium installation. Enable **Sound Switcher** in Millennium settings and reload Steam if requested.

Open Sound Switcher, choose your own audio (for the original request, use the separately supplied `message.wav`), preview it, and click **Kaydet**. Steam's message-sound notification setting must already be enabled. Test with a real incoming message while the recipient chat is unfocused. If Steam has already cached the old sound, restart Steam after saving.

To restore defaults, use **Varsayılana dön**. To remove the plugin, disable/uninstall it in Millennium and restart Steam. Steam's original audio files are never edited.

## How this prototype works

The frontend and Steam Community webview preload install narrowly matched HTMLMediaElement.play, fetch and XMLHttpRequest response wrappers in their respective JavaScript realms. Known target basenames are `steam_new_chat_message` and `ui_steam_message_old_smooth`. Other sound names pass through unchanged. Replacement playback failure falls back to the original.

The saved volume is applied to the WAV samples, so both covered playback paths use the selected gain. Each realm refreshes configuration every two seconds. If the backend stops responding, replacement expires after twelve seconds. Reload Steam after disabling the plugin to fully remove wrappers.

### Known limitations

- Steam may use a native audio API, a previously cached buffer, a different filename or a realm that Millennium does not inject into. Those paths are not intercepted.
- Audio CSP/autoplay restrictions may reject replacement playback. The fallback retains the old sound.
- The diagnostics counter covers only the current frontend realm. Zero does not prove the webview hook failed.
- Settings use a separate file because the native config limit is 256 KB. Large RPC payloads still need live-client testing.
- The file picker and native HTML controls have not been tested in Steam's UI. Gamepad navigation is not implemented.
- Current behavior targets private messages only. Online-friend, game-join, group and other notification sounds are future work.
- Stored audio is configuration data, not a per-account sound library. Do not attach your Millennium configuration to public bug reports.

## Verification

`node --test tests/runtime.test.mjs` needs no third-party dependencies. Tests cover exact target matching, pass-through behavior, replacement failure, restoring the original methods, fetch routing, and PCM16 WAV conversion/gain. They do not simulate Millennium or Steam.

Before publishing a release, follow [TESTING.md](TESTING.md). The included GitHub workflow runs these tests and attempts a compiler build; its first run also remains unverified.

## 0.1.5 investigation

The locally installed Steam steamui/sp.js calls AudioPlaybackManager.PlayAudioURL with ui_steam_message_old_smooth.m4a. Its StartPlayback uses axios.get(url, {responseType: "arraybuffer"}) followed by decodeAudioData. Version 0.1.5 adds replacement of completed successful GET XHR arraybuffer responses for the known message filenames. Network timing, status and original bytes remain intact for other requests or when disabled. Live interception is still awaiting user verification.

## 0.1.5 persistence fix

A live-client report confirmed a 256 KB Millennium config-value cap. Audio is now stored in a separate plugin-specific local settings.json file, with write/read verification and a previous-save .bak backup. The backend caches the document for polling. Neither file is deleted by restoring defaults; the current file then contains empty defaults. To remove imported audio completely, disable the plugin and delete its sound-switcher config folder, including .bak and .pending files.
